## 📝 January 12, 2026 - Search Algorithms & Rod Cutting Scenarios 🔍⚙️
### What I Learned Today: 💡

🔍 **Linear Search**
- O(n) time complexity, iterates through each element sequentially
- Simple but slow for large datasets
- Best for unsorted data or small collections

🎯 **Binary Search**
- O(log n) time complexity, divides search space in half each iteration
- Requires sorted data
- Much faster for large datasets

- **Scenario B**: Custom order added (e.g., 3.5ft at premium price), recalculate optimal cuts
  
- **Scenario C**: Compare optimized vs naive cutting strategy to visualize revenue impact

  - Handle last remaining unit case
  - Time Complexity: O(n) for search, O(1) for unlinking

  - Allows alphanumeric, dots, underscores, hyphens before @
  - Requires domain with valid TLD extension

- **Phone Number**: `^(\+\d{1,3}[-.\s]?)?\d{3}[-.\s]?\d{3}[-.\s]?\d{4}$`
  - Matches international phone formats
  - Optional country code with +
  - Flexible separators (hyphen, dot, space)

- **Credit Card**: `^\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}$`
  - Validates 16-digit card numbers
  - Allows optional separators between groups
  - Prevents invalid card formats

- **URL Validation**: `^https?:\/\/(www\.)?[a-zA-Z0-9.-]+\.[a-zA-Z]{2,}(\/.*)?$`
  - Matches HTTP/HTTPS URLs
  - Optional www subdomain
  - Validates domain structure

- **Password Strength**: `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]{8,}$`
  - Enforces minimum 8 characters
  - Requires uppercase, lowercase, digit, special character
  - Uses positive lookahead assertions for validation
